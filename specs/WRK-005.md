# Prepare a Candidate for Integration

## Intent

A developer or agent should be able to explicitly close Develop at one exact
committed checkpoint, publish it, and prove that published candidate ready for
Integration.

## Scenarios

### Complete Develop Explicitly

_Given_ every planned Develop Task is terminal
_And_ no unresolved Develop failure remains
_And_ the worktree is clean at the latest checkpoint
_When_ the developer runs `rapport develop complete`
_Then_ Rapport records that checkpoint as explicitly completed Develop
_And_ directs the developer to start or update Integration
_But_ runs no build, test, push, pull-request, or review side effect

### Keep Develop Open by Default

_Given_ Work has no recorded Develop Action Tasks
_And_ its latest checkpoint is clean
_When_ the developer inspects Work
_Then_ Rapport still treats Develop as open
_And_ directs the developer to `rapport develop complete`

### Prepare a Published Candidate

_Given_ explicitly completed Develop has been published through Integration
_When_ all affected Context build signoffs have current passing proofs
_And_ the published candidate has current passing Review proof with every
finding reconciled
_Then_ Rapport records that exact published candidate as prepared for merge

### Candidate Changes After Preparation

_Given_ a candidate was prepared
_When_ its commit, content, affected policy, or review instructions change
_Then_ Rapport retains the prior evidence as history
_But_ Develop must be explicitly completed and the active Integration updated
_And_ the changed candidate is not prepared until required Build and Review
proof is current for the updated pull-request SHA

### Work Is Not Ready

_Given_ required Build or Review proof is missing, failing, unresolved, running,
or stale
_When_ the developer asks whether Work is ready
_Then_ Rapport identifies the unmet requirement
_And_ presents the next Develop, Build, or Review action
