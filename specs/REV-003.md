# Prepare a Component Review Without Lifecycle State

## Intent

A human or agent should receive the architecture and actionable benchmarks needed
to review selected repository components using their own process and tools.

## Scenarios

### Generate a Review Prompt

_Given_ one or more repository-relative component paths
_When_ the reviewer runs `rapport review` with those paths
_Then_ Rapport emits a Markdown review prompt with applicable ancestor and local
purpose, ownership, boundaries, and full benchmark definitions
_And_ preserves stable identifiers, rationale, examples, and source file paths
_And_ requires no Work, commit, build proof, GitHub authentication, or agent service
_But_ it does not execute the review, collect a diff, or record acceptance

### Resolve Reusable Standards

_Given_ components include reusable packs directly or transitively
_When_ Rapport prepares the review prompt
_Then_ it includes each identical benchmark once while retaining source references
_And_ rejects conflicting definitions, cycles, and unresolved includes explicitly
_And_ emits no partial prompt if context resolution fails

### Read Authored Architecture

_Given_ a context declares a namespace, purpose, optional component type, ownership,
boundaries, and local rules with rationale and avoid/prefer examples
_When_ Rapport reads that context
_Then_ version fields, allocation counters, and lifecycle state are not prerequisites
_And_ unsupported fields produce explicit errors
