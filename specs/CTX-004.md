# Validate Architecture and Benchmark Declarations

## Intent

A maintainer should know that repository architecture and review standards are
complete and unambiguous before handing them to a reviewer.

## Scenarios

### Validate Repository Context

_Given_ repository-owned contexts and reusable standards packs
_When_ the maintainer runs `rapport context validate`
_Then_ Rapport checks schemas, stable identifiers, ownership references, and includes
_And_ checks every component's effective standards for conflicting definitions
_And_ validates direct component membership, generated producer and consumer
declarations, relative kustomization targets, and generated dependency cycles
_And_ reports an actionable error for missing context or incompatible declarations
_And_ does not invoke repository tools, change files, or consult Work state

### Validate a Selected Area

_Given_ a selected component or directory containing components
_When_ the maintainer validates that path
_Then_ Rapport validates discovered schemas and pack references
_And_ checks applicable inherited and local standards for the selected components

### Validate Component Dependencies

_Given_ contexts declare component membership and generated inputs or outputs
_When_ Rapport reads or validates those contexts
_Then_ it preserves the declarations and their source paths
_And_ resolves each generated input to a declared producer output
_And_ rejects missing producers, missing outputs, invalid paths, and dependency cycles
_But_ it does not inherit a parent's generation instructions into child contexts

### Reject Removed Lifecycle Configuration

_Given_ a context still declares review grades or build signoffs
_When_ Rapport reads the context
_Then_ it identifies the removed field and its source path
_And_ explains that acceptance and build policy belong to repository tooling
_But_ it does not silently discard the declaration
